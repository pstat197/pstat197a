What does “connect GitHub to RStudio” mean?

There are three separate pieces:

  1. Git tracks changes on your own computer.

  2. GitHub hosts the remote copy of the repository online.

  3. RStudio gives you buttons for common Git actions such as commit, pull, and push.

RStudio does not have a separate GitHub account that you log into.

To send changes to GitHub, Git needs a way to authenticate you.

What is a PAT?

PAT = Personal Access Token

A PAT is a special string generated by GitHub that can authenticate Git operations on your behalf.

Think of it as a replaceable, limited-purpose password for Git.

A PAT:

  • is generated from your GitHub account;

  • can be limited to particular kinds of access;

  • can expire;

  • can be revoked without changing your GitHub password.

Why am I being asked for a PAT instead of my password?

GitHub does not accept your normal account password for Git operations over HTTPS.

When Git or RStudio asks for a password while connecting to GitHub:

paste your PAT instead of your GitHub password.

Your normal GitHub password will not work for this.

Important

Never paste your PAT into an R script, Quarto document, GitHub repository, Canvas submission, or class chat.

Create a PAT: navigate to the settings

On github.com:

  1. Click your profile picture in the upper-right corner.
  2. Click Settings.
  3. Scroll to the bottom of the left sidebar.
  4. Click Developer settings.
  5. Click Personal access tokens.
  6. Click Tokens (classic).
  7. Choose Generate new token > Generate new token (classic).

GitHub may ask you to confirm your password or two-factor authentication.

Create a PAT: name and expiration

For Note, enter something descriptive, such as:

PSTAT 197A RStudio

For Expiration:

  • choose an expiration that lasts at least through the course;

  • 90 days will be more than enough for this quarter;

  • do not choose an unnecessarily long expiration.

If the token expires later, you can simply make a new one.

Create a PAT: choose the scope

Under Select scopes, select:

public_repo

You do not need full access to private repositories for this course.

public_repo allows the token to work with public repositories that your GitHub account has permission to modify.

The PSTAT 197A course repositories are public.

Important

Do not select permissions simply because they sound useful. For this course, public_repo is sufficient.

Generate and COPY the PAT

Scroll to the bottom and click Generate token.

GitHub will display the token.

Copy it immediately.

GitHub will not show you the complete token again after you leave the page.

Example of the GitHub token display after creation. Source: GitHub Docs.

Treat the PAT like a password

Your token will look something like:

ghp_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Do not:

  • show it to another student;

  • email it to anyone;

  • put it in an R file;

  • commit it to GitHub;

  • include it in a screenshot.

If you accidentally expose it, revoke it on GitHub and create a new one.

Go back to RStudio

Return to the authentication popup.

When asked for:

Username

your GitHub username

When asked for:

Password / Personal Access Token

paste the PAT you just created

The PAT goes in the password field.

Do not enter your normal GitHub password.

Will I have to enter the PAT every time?

Usually, no.

Git can store the credential using your computer’s credential system so that RStudio can reuse it.

If your computer keeps asking for the PAT every time you pull or push, run this in the R Console:

install.packages("gitcreds")
gitcreds::gitcreds_set()

When prompted, paste your PAT.

This stores the credential through Git’s credential system rather than putting the PAT in your R code.

Git identity is a different thing

Authentication answers:

Are you allowed to push to this GitHub repository?

Your Git identity answers:

Whose name and email should appear on this commit?

These are separate settings.

In the RStudio Terminal, run:

git config --global user.name "Your Name"
git config --global user.email "YOUR_GITHUB_EMAIL"

Use the email address associated with your GitHub account.

Check your Git identity

In the RStudio Terminal:

git config --global user.name
git config --global user.email

You should see your own name and email.

You generally only need to configure these once on your computer.

Check that you are connected to the correct repository

In the RStudio Terminal, run:

git remote -v

You should see:

origin  https://github.com/pstat-197a-fall2026/github-basics-template (fetch)
origin  https://github.com/pstat-197a-fall2026/github-basics-template (push)

If the URL points somewhere else, stop before pushing.

RStudio’s Review Changes window. Source: Posit RStudio User Guide.

Commit does NOT mean upload

A commit records the change in the Git repository on your computer.

It does not automatically send anything to GitHub.

To send the commit to the remote repository, you still need to:

push

So the basic sequence is:

pull -> edit -> stage -> commit -> push

Push your commit

Immediately before pushing, it is a good idea to Pull again because many students may be updating the repository.

Then click Push in RStudio.

If Git asks for authentication:

  • username = your GitHub username;

  • password = your PAT.

If the push succeeds, your commit is now on GitHub.

If your push is rejected because the remote changed

This is likely to happen if many people may be pushing at once.

If you see a message that your branch is behind the remote:

  1. Pull again.
  2. Let Git incorporate the new commits.
  3. Push again.

Because everyone is creating a different USERNAME-about.md file, these updates should not conflict with one another.

Troubleshooting: authentication failed

If GitHub rejects your authentication, check:

  • Did you enter your GitHub username?

  • Did you paste the PAT, not your GitHub password?

  • Is the PAT still active and unexpired?

  • Did you give the classic PAT the public_repo scope?

  • Have you accepted the invitation to the pstat-197a-fall2026 organization?

A public repository can be viewed and cloned by anyone, but pushing directly requires write permission.

Troubleshooting: no Git tab in RStudio

First make sure you opened the RStudio project created from the repository, not an unrelated RStudio session.

Then check:

Tools > Global Options > Git/SVN

Make sure:

  • Enable version control interface for RStudio projects is checked;

  • RStudio shows a Git executable.

You can also run in the Terminal:

git status

Troubleshooting: wrong repository

Run:

git remote -v

For this activity, origin should point to:

https://github.com/pstat-197a-fall2026/github-basics-template

Do not push until you know which remote repository your project is connected to.

If you are not yet a member of the organization

You can view and clone the public repository, but you cannot push directly to it without write access.

If you have not yet been added to the course organization:

  1. complete the Git/RStudio/PAT setup;
  2. do not worry if the final direct push is rejected;
  3. follow the alternate fork/pull-request instructions provided by the instructor.

Once your organization invitation is accepted, the normal push workflow will work.

The workflow to remember

For routine work:

PULL
  |
EDIT FILES
  |
STAGE
  |
COMMIT
  |
PULL AGAIN IF NEEDED
  |
PUSH

Authentication with your PAT is what allows the final communication with GitHub.
